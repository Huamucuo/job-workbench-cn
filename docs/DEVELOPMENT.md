# 公开构建流程

main 保存可复现的开发状态。功能分支通过 PR 提交需求、实现、测试与限制，独立审查后合并。维护者应实际配置禁止强推/删除、要求测试与 PR；单人维护时独立审查记录不能冒充 GitHub 人类批准。

每次版本说明引用真实提交。开发预览使用 prerelease；Stable 另行验收、批准和回退。首次源码公开可以先于稳定版。

CI 只有离线测试与本机构建，contents: read、无持久凭证，无生产 Secrets、定时采集、部署或自动发布。原更新部署流程不在本候选中。

首次上传前核对清单/哈希/许可和全部待推历史。保留已有父提交，不以新造历史掩盖旧敏感提交。不公开 review 报告、Git 内部日志、个人配置或产物。
