# Engine operation cancellation review fix

Status: implementation and focused verification complete. Canonical source ready for coordinator rebuild; this task did not build, commit, release or edit mirrored files.

## Implementation

- `public/autofill/engine.js`: engine version 0.4.1; legacy `apply(scanId,items)` / `prepareGroups(counts)` remain available. Optional guard is strict `{operationId,contextKey,expiresAt}`: UUID; empty or sha256:64 lowercase hex context; finite deadline after validation time and at most 120000ms away. Unknown/extra guard keys, malformed guard and absent watcher reject before writes.
- `cancelOperation(operationId)` registers cancellation even before an operation begins. Private isolated-world map holds up to 512 unexpired IDs for 120s. Saturation fails closed for 120s rather than evicting a cancellation and reviving an interrupted operation. No storage/network/profile transfer added.
- Guard checks call the independent existing watcher; they run before each native write, checkbox/radio member activation, custom trigger/choice and group-add click; after event-induced changes; during every async observation iteration; and before final success classification.
- Each operation captures its starting href. Both current location and watcher snapshot URL must still match, even if known application context remains identical. Context, URL, cancellation, expiry or watcher failure is latched for that operation; a context that changes back cannot resume it.
- Interrupted fields that were actually written remain `pending` with explicit Chinese manual-review reason; later untouched fields are `skipped`. Existing failures remain failures. Cancellation during final settling cannot claim provisional writes as filled. Add-group result retains actual click count; an already queued website callback may still create the first requested group, but no further engine clicks occur.
- Requested observer aliases added in `public/autofill/page-watch.js`: explicit Greenhouse `gh_jid`, iTalent `inviteKey` and `elinkId`, SHA-256 context only. Invitation key takes priority over e-link when both exist. Generic `id` is still unknown. `read().url` retains its specified full current-URL contract; no raw ID is returned as contextKey or a separate identifier.

## Required post-await target-race repair

The next independent review identified a material race: real async watcher/hash checks occurred after an initial target/value check, then old setters or click references were used without a synchronous target recheck. This was fixed within the same owned source files; all failures remain recorded.

- Added watcher `matchesContext(key)`, a narrow synchronous boolean helper. `read()` keeps its original exact metadata result. The helper recomputes observed identifiers privately and compares with the last genuine read's document-local key/raw identifier pair; neither raw identifiers nor field/profile values are exported. Empty expected key only matches when current context is still unidentified, so unknown-to-known changes stop.
- Guarded operations check immediate href/deadline/cancellation and synchronous context after the hash await and again directly beside each write/click, then synchronously verify native/custom control identity, label/descriptor/group, safe bindings/options and existing value. Grouped checkbox/multiple-select writes compare to the logical partial value produced by this operation; user changes cannot be adopted as an expected baseline. Custom selections recapture exact options/member identity after the guard wait. Add buttons recapture unique safe identity, text/type/form and record identity/count/descriptors/occupied values. No awaited call remains between the final synchronous recheck and actual setter/click.
- Guarded radios select the desired member without trying to uncheck the previously selected radio by clicking it. Guarded multi-select skips a no-change option before a disabled-write check; an unselected disabled placeholder does not block other legal values. Requested disabled choices remain refused. Legacy unguarded behavior is unchanged.
