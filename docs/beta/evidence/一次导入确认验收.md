# 导入一次确认保存 UX 修改报告

用户最新明确要求：软件简单易懂，不要重复操作。本轮只简化导入与空档案入口；未删除原功能，未改vault、bridge、engine、构建文件或他人QA脚本，无commit/push。

## 新普通流程

空档案：填写12字符以上口令 → 导入已有简历（直接打开真实PDF/DOCX文件选择器）→ 预览、改候选/冲突并勾选核对 → 确认导入并加密保存。

有有效档案/恢复草稿：继续解锁或恢复，不出现建立新空档案的导入入口。新增入口只在存储读取成功且无有效档案/恢复草稿时显示。新建空白档案保留为secondary；原“选择加密档案导入”改名“恢复加密备份”，操作与旧加密备份验证保持不变。

导入默认主按钮一次完成已审阅结果的验证、应用到draft、profile.save加密与storage.commitVault CAS。只有save成功才关闭预览并显示成功。对于扩展/共享主档案，成功提示扩展可立即使用；离线位置提示其真实保存位置。

高级选项折叠保留“仅加入草稿，稍后完善”。此路径不写有效档案，手动/闲置锁定仍仅保留加密恢复草稿，后续需要显式保存。导入完成后的普通手动编辑依然显式保存，没有autosave。

## 失败保护

- 未勾选核对、身份冲突未确认：主按钮和draft-only均不可用，model helper也拒绝。
- 邮箱/日期等不完整格式：验证失败前不替换draft，不写原有效密文；预览输入保留，可以修正后重试。
- 保存/CAS/连接失败：预览保持打开，错误显示在预览内，已导入draft保留；原有效档案不会被本次操作覆盖。
- 正在加密保存时预览inert，避免同一次确认被重复触发或误取消。
- 预览期间draft变化则拒绝覆盖；失败重试只接受同一份已应用且没有额外手动变化的draft。
- 取消/仅加入草稿由用户明确操作，保留现有恢复、备份和后续完善能力。
